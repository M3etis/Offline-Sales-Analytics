## Установка

### Автоматическая установка

**macOS / Linux:**

```bash
git clone <url> sales-analytics
cd sales-analytics
chmod +x start.sh
./start.sh
```

**Windows (PowerShell):**

```powershell
git clone <url> sales-analytics
cd sales-analytics
powershell -ExecutionPolicy Bypass -File start.ps1
```

Скрипт автоматически:

- Устанавливает Ollama если отсутствует
- Скачивает модель если отсутствует
- Создаёт Python venv и устанавливает зависимости
- Устанавливает npm-зависимости фронтенда
- Генерирует SECRET_KEY
- Запускает бэкенд и фронтенд
- Открывает браузер

### Ручная установка

#### Шаг 1: Зависимости системы

```bash
# macOS
brew install python@3 node ffmpeg ollama

# Ubuntu/Debian
sudo apt update
sudo apt install python3 python3-venv nodejs npm ffmpeg
# Ollama: https://ollama.com/download
```

#### Шаг 2: Бэкенд

```bash
python -m venv venv
source venv/bin/activate        # Linux/macOS
# venv\Scripts\activate         # Windows

pip install -r requirements.txt
```

#### Шаг 3: Фронтенд

```bash
cd frontend
npm install
cd ..
```

#### Шаг 4: Ollama и модель

```bash
ollama serve &                   # Запуск Ollama сервера
ollama pull qwen2.5:14b          # Скачивание модели (9 ГБ)
```

#### Шаг 5: Конфигурация

```bash
cp .env.example .env
# Отредактировать .env:
#   SECRET_KEY=<секретный ключ минимум 32 символа>
#   OLLAMA_MODEL=qwen2.5:14b
```

#### Шаг 6: Запуск

```bash
# Терминал 1: бэкенд
source venv/bin/activate
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# Терминал 2: фронтенд
cd frontend
npm run dev
```

## Desktop-версия (Electron)

Приложение доступно как автономное desktop-приложение. Всё в одном DMG-файле — ничего дополнительно устанавливать не нужно.

### Что включено

| Компонент   | Описание                      |
| ----------- | ----------------------------- |
| Electron    | Оболочка приложения           |
| Frontend    | Собранный React-интерфейс     |
| Backend     | Python-бинарник (PyInstaller) |
| Ollama      | Встроенный LLM-сервер         |
| qwen2.5:14b | Языковая модель (8.4 ГБ)      |

### Размер сборки

| Платформа             | Размер  |
| --------------------- | ------- |
| macOS (Apple Silicon) | ~8.7 ГБ |
| macOS (Intel)         | ~8.7 ГБ |

### Установка Desktop

1. Скачайте DMG-файл для вашей платформы
2. Откройте DMG, перетащите приложение в Applications
3. При первом запуске: правый клик → Открыть (Gatekeeper)

> Приложение полностью автономно. Ollama и модель запускаются автоматически. Python и Node.js не требуются.

### Сборка Desktop из исходников

```bash
cd desktop
npm install

# Полная сборка (Ollama + модель + frontend + backend + Electron)
npm run package
```

Этапы сборки по отдельности:

```bash
cd desktop

# 1. Скачать Ollama binary
bash scripts/download-ollama.sh

# 2. Упаковать модель qwen2.5:14b (нужна скачанная локально)
bash scripts/bundle-model.sh

# 3. Собрать frontend
bash scripts/build-frontend.sh

# 4. Собрать backend binary
bash scripts/build-backend.sh

# 5. Скомпилировать TypeScript
npx tsc -p tsconfig.json

# 6. Собрать DMG
npx electron-builder --config electron-builder.yml
```

### Dev-режим Desktop

```bash
cd desktop
npm install
npm run dev
```

Запускает frontend dev server, backend и Electron окно с горячей перезагрузкой.

## Использование

1. Войдите под `admin`
2. **Загрузите данные**: Настройки → Загрузка данных (CSV, XLSX, DB) или «Демо-данные»
3. **Задайте вопрос**: Вкладка «Ассистент» — текстом или голосом
4. **Дашборд**: Автоматические KPI, графики динамики, распределения
5. **Настройте ИИ**: Настройки → Инструкции ассистента

## Алгоритмы обработки запросов

### Пайплайн обработки вопроса пользователя

```
Вопрос пользователя
        │
        ▼
┌───────────────────┐
│ 1. Классификация  │  LLM определяет intent: kpi, comparison, top,
│    интента         │  drop, chart, summary, sql
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 2. Проверка кеша  │  MD5-хеш вопроса + dataset_id + extended
│                   │  → llm_cache таблица или chat_messages fallback
└───────┬───────────┘
        │ (промах)
        ▼
┌───────────────────┐
│ 3. Подготовка     │  Загрузка манифеста (профили колонок)
│    схемы          │  Формирование промпта с типом таблицы,
│                   │  колонками, связями, примерами значений
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 4. Генерация SQL  │  LLM генерирует SELECT-запрос
│                   │  → извлечение SQL из ответа (_extract_sql)
│                   │  → коррекция LIMIT (_adjust_limit)
│                   │  → исправление ошибок (_fix_cte_errors):
│                   │    - галлюцинации колонок
│                   │    - forward references в CTE
│                   │    - MAX/MIN подзапросы → ORDER BY
│                   │  → замена имен таблиц (_remap_table_names)
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 5. Валидация SQL  │  Проверки:
│                   │  - только SELECT/WITH
│                   │  - нет DML-ключевых слов
│                   │  - таблицы разрешены (dataset_*, CTE)
│                   │  - SQL-функции не ловятся как таблицы
│                   │  - санитизация (LIMIT, комментарии)
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 6. Выполнение SQL │  DuckDB execute → list[dict]
│                   │  Decimal → str конвертация
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 7. Генерация      │  LLM формирует текстовый ответ
│    ответа          │  → программный prepend "Найдено: N записей."
│                   │  → запрет на упоминание валюты
│                   │  → запрет на упоминание количества (LLM)
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 8. Сохранение     │  Кеш (llm_cache) + история (chat_messages)
│    и отдача        │  WebSocket стриминг токенов
└───────────────────┘
```

### Генерация SQL: исправление ошибок

Система автоматически исправляет типичные ошибки LLM:

| Ошибка                  | Пример                                                               | Исправление                                                   |
| ----------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------- |
| Галлюцинация колонок    | `pu.amount` → `p2.product_count * p2.product_price`                  | Маппинг `_HALLUCINATED_COLUMNS`                               |
| Forward reference в CTE | `JOIN p2 ON sc.customer_id = pu.customer_id` (pu не определён)       | `_fix_forward_references()` перемещает условие после JOIN pu  |
| MAX/MIN подзапрос       | `WITH max AS (SELECT MAX(markup)...) WHERE markup = (SELECT max...)` | `_fix_max_min_subquery()` → `ORDER BY markup DESC LIMIT 1`    |
| Лишний JOIN             | `JOIN purchases pu ON ...` когда `pu.*` не используется              | Удаление неиспользуемых JOIN                                  |
| Неверный LIMIT          | "покажи все товары" → `LIMIT 10`                                     | `_adjust_limit()` → `LIMIT 500` при ключевых словах "все/всё" |

        │ Текст
        ▼

        ▼

## Решение типичных проблем

### Бэкенд не стартует: `INTERNAL Error: Failure while replaying WAL file`

Повреждение WAL-файла DuckDB. Система автоматически восстанавливается — удаляет повреждённый `.wal` файл и переподключается. Если автоматическое восстановление не сработало:

```bash
rm data/processed/sales.duckdb.wal
./start.sh
```

### WebSocket не подключается при старте

При запуске бэкенд выполняет warmup Ollama (до 15 сек), что может блокировать event loop. WebSocket автоматически переподключается через 3 сек. Если подключение не восстанавливается:

1. Убедитесь что Ollama запущена: `curl http://127.0.0.1:11434/api/tags`
2. Проверьте логи: `cat logs/backend.log | grep "WS:"`
3. Перезапустите: `Ctrl+C` → `./start.sh`

### Ollama warmup failed

Если Ollama не установлена или модель не скачана, бэкенд стартует с предупреждением. Функции ИИ будут недоступны. Решение:

```bash
ollama serve                    # Запуск Ollama
ollama pull qwen2.5:14b         # Скачивание модели
```

### Deprecation warnings при запуске

Предупреждения `regex has been deprecated, please use pattern` — безопасны, не влияют на работу. Устранены в актуальной версии.

### Порт 8000 или 5173 занят

Скрипт `start.sh` автоматически освобождает порты. Если запускаете вручную:

```bash
lsof -i :8000 -t | xargs kill -9
lsof -i :5173 -t | xargs kill -9
```
