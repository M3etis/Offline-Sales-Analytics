## Установка

### Автоматическая установка

**macOS / Linux:**

```bash
git clone <url> sales-analytics
cd sales-analytics
chmod +x start.sh
./start.sh
```

**Windows (PowerShell):**

```powershell
git clone <url> sales-analytics
cd sales-analytics
powershell -ExecutionPolicy Bypass -File start.ps1
```

Скрипт автоматически:

- Устанавливает Ollama если отсутствует
- Скачивает модель если отсутствует
- Создаёт Python venv и устанавливает зависимости
- Устанавливает npm-зависимости фронтенда
- Генерирует SECRET_KEY
- Запускает бэкенд и фронтенд
- Открывает браузер

### Ручная установка

#### Шаг 1: Зависимости системы

```bash
# macOS
brew install python@3 node ffmpeg ollama

# Ubuntu/Debian
sudo apt update
sudo apt install python3 python3-venv nodejs npm ffmpeg
# Ollama: https://ollama.com/download
```

#### Шаг 2: Бэкенд

```bash
python -m venv venv
source venv/bin/activate        # Linux/macOS
# venv\Scripts\activate         # Windows

pip install -r requirements.txt
```

#### Шаг 3: Фронтенд

```bash
cd frontend
npm install
cd ..
```

#### Шаг 4: Ollama и модель

```bash
ollama serve &                   # Запуск Ollama сервера
ollama pull qwen2.5:14b          # Скачивание модели (9 ГБ)
```

Модель можно не качать вручную: в «Настройки → Настройки ассистента» приложение определит конфигурацию компьютера (память, видеоядро, свободное место), порекомендует подходящую модель и установит её одной кнопкой. Выбор сохраняется и важнее значения `OLLAMA_MODEL` из `.env`.

#### Шаг 5: Конфигурация

```bash
cp .env.example .env
# Отредактировать .env:
#   SECRET_KEY=<секретный ключ минимум 32 символа>
#   OLLAMA_MODEL=qwen2.5:14b
```

#### Шаг 6: Запуск

```bash
# Терминал 1: бэкенд
source venv/bin/activate
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# Терминал 2: фронтенд
cd frontend
npm run dev
```

## Desktop-версия (Electron)

Приложение доступно как автономное desktop-приложение. Всё в одном DMG-файле — ничего дополнительно устанавливать не нужно.

### Что включено

| Компонент | Описание                                                                 |
| --------- | ------------------------------------------------------------------------ |
| Electron  | Оболочка приложения                                                      |
| Frontend  | Собранный React-интерфейс                                                |
| Backend   | Python-бинарник (PyInstaller)                                            |
| Ollama    | Встроенный LLM-сервер                                                    |
| Модель    | Выбирается при сборке: текущая, одна из рекомендуемых или без модели     |

### Размер сборки

Размер установщика ≈ 300 МБ + размер встроенной модели: 3B — ~1,9 ГБ, 7B — ~4,7 ГБ, 14B — ~9 ГБ, 32B — ~20 ГБ. Сборка без модели самая лёгкая — подходящую модель приложение предложит скачать само.

### Где хранятся данные

База, загруженные файлы и логи лежат в каталоге данных пользователя, а не внутри приложения, — поэтому переживают обновления и работают при установке в каталог только для чтения:

| ОС      | Каталог                                              |
| ------- | ---------------------------------------------------- |
| macOS   | `~/Library/Application Support/Sales Analytics/`     |
| Windows | `%APPDATA%\Sales Analytics\`                         |
| Linux   | `~/.config/Sales Analytics/`                         |

Там же — `secret.key`: ключ подписи токенов, свой для каждой установки (создаётся при первом запуске, права `600`). Модели Ollama хранятся в `~/.ollama/models`.

### Установка Desktop

1. Скачайте DMG-файл для вашей платформы
2. Откройте DMG, перетащите приложение в Applications
3. При первом запуске: правый клик → Открыть (Gatekeeper)

> Приложение полностью автономно. Ollama и модель запускаются автоматически. Python и Node.js не требуются.

### Сборка Desktop из исходников

```bash
cd desktop
npm install

# Полная сборка (Ollama + модель + frontend + backend + Electron)
npm run package
```

Этапы сборки по отдельности:

```bash
cd desktop

# 1. Скачать Ollama binary
bash scripts/download-ollama.sh

# 2. Встроить модель (спросит, какую; --model current|none|qwen2.5:7b — без вопросов)
bash scripts/bundle-model.sh

# 3. Собрать frontend
bash scripts/build-frontend.sh

# 4. Собрать backend binary
bash scripts/build-backend.sh

# 5. Скомпилировать TypeScript
npx tsc -p tsconfig.json

# 6. Собрать DMG
npx electron-builder --config electron-builder.yml
```

### Dev-режим Desktop

```bash
cd desktop
npm install
npm run dev
```

Запускает frontend dev server, backend и Electron окно с горячей перезагрузкой.

## Запуск

После запуска `start.sh`/`start.ps1` сам открывает браузер и печатает итоговые адреса. По умолчанию:

- **Фронтенд**: http://localhost:5173 (или http://127.0.0.1:5173)
- **Бэкенд (Swagger)**: http://127.0.0.1:8000/docs
- **Health check**: http://127.0.0.1:8000/health

Если порт занят другим приложением, скрипт берёт ближайший свободный (5174, 8001, …) — открывайте адрес, который он напечатал. Браузер открывается на `localhost`: вход и настройки хранятся в браузере по адресу страницы и сохраняются между запусками. Порт выбирается свободным и на IPv4, и на `::1`, поэтому `localhost` не попадёт в чужое приложение (например, Docker на `[::]:5173`). Если порт сменился (5174 вместо 5173), это другой адрес — войти придётся заново.

Остановка — `Ctrl+C` в окне скрипта или `./stop.sh` (Windows: `powershell -ExecutionPolicy Bypass -File stop.ps1`). Останавливаются бэкенд и фронтенд этого проекта на любом порту; Ollama — только если её запустил скрипт запуска. Ollama, запущенную вами (приложение, служба, `ollama serve`), скрипт оставляет работать.

### Учетные записи по умолчанию

| Логин | Пароль | Роль          |
| ----- | ------ | ------------- |
| admin | admin  | Администратор |
| user  | user   | Пользователь  |

> Смените пароли после первого входа!

## Использование

1. Войдите под `admin`
2. **Загрузите данные**: Настройки → Загрузка данных (CSV, XLSX, XLS, DB) или «Демо-данные»
3. **Задайте вопрос**: Вкладка «Ассистент» — текстом или голосом
4. **Дашборд**: Автоматические KPI, графики динамики, распределения
5. **Настройте ИИ**: Настройки → Настройки ассистента, Словарь колонок
6. **Модель**: Настройки → Настройки ассистента — приложение определит память и видеоядро, порекомендует модель, скачает и переключит её без перезапуска

Права пользователей задаются по разделам (Настройки → Пользователи) и проверяются и в интерфейсе, и на сервере.

## Модули и компоненты

### Бэкенд (`app/`)

#### Ядро (`app/core/`)

| Файл              | Назначение                                                                                                 |
| ----------------- | ---------------------------------------------------------------------------------------------------------- |
| `config.py`       | Pydantic-настройки из `.env`: путь к БД, URL Ollama, модель Whisper, SECRET_KEY, лимиты                    |
| `dependencies.py` | DI-контейнер: `DatabaseManager` (пул соединений DuckDB), `get_db`, `get_current_user`, `get_current_admin` |
| `security.py`     | JWT-токены (создание/валидация), bcrypt-хеширование паролей                                                |

#### API-роутеры (`app/api/routes/`)

| Файл           | Назначение                                                                           |
| -------------- | ------------------------------------------------------------------------------------ |
| `auth.py`      | OAuth2-логин с rate-limiting (5 попыток/минута)                                      |
| `data.py`      | Загрузка (CSV/XLSX/XLS/DB/URL), предпросмотр, удаление, переименование датасетов и групп |
| `analytics.py` | KPI, продажи по категориям/регионам/менеджерам, таймлайн, топ товаров, аномалии      |
| `ai.py`        | Синхронный и SSE-streaming запросы к ИИ                                              |
| `sessions.py`  | CRUD сессий, сообщения, feedback (лайки/дизлайки), статистика                        |
| `settings.py`  | Инструкции ИИ, системные настройки, TTS-голос, очистка кеша/сессий                   |
| `users.py`     | Управление пользователями (только admin): создание, редактирование, удаление, пароли |
| `voice.py`     | STT (транскрибация), TTS (синтез речи, файловый и streaming)                         |
| `ws.py`        | WebSocket для real-time стриминга ответов ИИ                                         |

#### Сервисы (`app/services/`)

| Файл             | Назначение                                                                                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `analytics.py`   | Бизнес-логика: KPI, агрегации, сравнение периодов, поиск аномалий, ABC-анализ. Динамический маппинг колонок (`_map_columns`), безопасные параметризованные запросы                                                |
| `pipeline.py`    | Общий конвейер ответа для HTTP и WebSocket: выбор таблиц группы, готовый расчёт или SQL модели, цикл исправления SQL, промпт ответа, постобработка (разряды чисел, валюта)                                         |
| `insights.py`    | Проверенные расчёты типовых вопросов: итоги, разрезы, сравнения периодов, динамика, возвраты, клиенты и отток, скидки, ABC, прогноз, сводка, проверка качества данных                                              |
| `llm.py`         | Клиент Ollama (генерация SQL и ответа), контекст диалога, кеш ответов (`chat_messages` + подпись условий: модель, правила, режим), сохранение сообщений, HTTP-вход `process_question`                               |
| `streaming.py`   | WebSocket-вход: стриминг токенов, отмена запроса, уточнения; логика — в `pipeline.py`                                                                                                                              |
| `currency.py`    | Валюта ответов: настройка `local_currency` (или `LOCAL_CURRENCY`), время смены для сброса кеша                                                                                                                    |
| `ingest.py`      | Импорт данных: CSV (разделитель по заголовку), книги Excel по листам с поиском шапки и без строк «Итого», числа текстом → числа, даты → TIMESTAMP (формат по каждому значению), DB (DuckDB/SQLite), связи листов |
| `preanalysis.py` | Предвычисление манифеста: профили колонок (типы, null-rate, distinct, samples, stats), маппинг колонок, сохранение в `dataset_manifest`                                                                           |
| `column_dict.py` | Билингвальный словарь EN↔RU для колонок (350+ записей), маппинг-хинты для промптов; записи пользователя задают смысл (роль) колонки                                                                               |
| `voice.py`       | Whisper STT (в ThreadPoolExecutor), Edge TTS (async streaming), очистка текста для озвучки                                                                                                                        |

#### Доменные модули (`app/domain/`)

| Модуль                    | Назначение                                                                            |

## Алгоритмы обработки запросов

### Пайплайн обработки вопроса пользователя

Один конвейер (`app/services/pipeline.py`) для WebSocket и HTTP:

```
Вопрос пользователя
        │
        ▼
┌─────────────────────┐
│ 1. Кеш ответов      │  тот же вопрос, тот же набор данных, те же модель/правила/режим,
│                     │  без контекста диалога, новее загрузки данных и смены валюты
└───────┬─────────────┘
        │ (промах)
        ▼
┌─────────────────────┐
│ 2. Выбор таблиц     │  группа листов/таблиц → таблица продаж (по смыслу листа)
│                     │  и связанные справочники; роли колонок (column_roles)
└───────┬─────────────┘
        ▼
┌─────────────────────┐
│ 3. Разбор вопроса   │  период, разрез, показатель, фильтры по значениям;
│    и маршрут        │  неузнанные названия ищутся в данных
└───────┬─────────────┘
        │
   ┌────┴─────────────────────────────┐
   ▼                                  ▼
┌─────────────────────┐   ┌──────────────────────────────────┐
│ 4а. Готовый расчёт  │   │ 4б. SQL модели                    │
│  (insights.py):     │   │  схема со значениями колонок,     │
│  итоги, разрезы,    │   │  эталонные примеры → генерация →  │
│  сравнения, ABC,    │   │  проверка безопасности → до трёх  │
│  отток, прогноз…    │   │  попыток «ошибка → исправление»,  │
│                     │   │  ремонт имён колонок без модели   │
└───────┬─────────────┘   └──────────────┬───────────────────┘
        └──────────────┬─────────────────┘
                       ▼
┌──────────────────────────────────────────┐
│ 5. Ответ: числа форматирует код,         │
│    рейтинг и прямой ответ считает код,   │
│    модель только формулирует текст;      │
│    разряды и валюта сверяются с данными  │
└───────┬──────────────────────────────────┘
        ▼
┌─────────────────────┐
│ 6. Сохранение       │  история (chat_messages) = кеш; стриминг токенов
└─────────────────────┘
```

Если нужной колонки в данных нет (например, клиента или даты), ассистент отвечает честно, не выдумывая цифры. Проверка на 50 типовых вопросах — `docs/reports/qa-50-queries-2026-11-15.md`.

### Генерация SQL: исправление ошибок

| Ошибка                  | Пример                                                               | Исправление                                                   |
| ----------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------- |
| Искажённое имя колонки  | `brand` вместо `бренд`, `дата__` вместо `дата_текст`                 | `fix_unknown_column()` по ошибке DuckDB — только уверенная замена |
| Значение фильтра        | `'алматы'` при значении «Алматы»                                     | `fix_filter_values()`; артикулы и коды не подменяются          |
| Имя листа в SQL         | `FROM "Остатки на складе"`, `FROM Продажи t1, Возвраты t2`           | `remap_table_names()` → `dataset_*`                            |
| `TO_CHAR`               | `TO_CHAR(дата, 'YYYY-MM')`                                           | `strftime(дата, '%Y-%m')` с переводом формата                  |
| Forward reference в CTE | `JOIN p2 ON sc.customer_id = pu.customer_id` (pu не определён)       | `_fix_forward_references()` перемещает условие после JOIN pu  |
| MAX/MIN подзапрос       | `WITH max AS (SELECT MAX(markup)...) WHERE markup = (SELECT max...)` | `_fix_max_min_subquery()` → `ORDER BY markup DESC LIMIT 1`    |
| Неверный LIMIT          | "покажи все товары" → `LIMIT 10`                                     | `_adjust_limit()` → `LIMIT 500` при ключевых словах "все/всё" |

## Безопасность

- **SQL модели — только чтение.** Каждый запрос разбирается парсером самой DuckDB (`json_serialize_sql`): разрешены только `SELECT` по таблицам данных (`dataset_*`), без табличных функций, читающих файлы (`read_text`, `glob`, `read_csv`…), и без служебных таблиц (`users`, `chat_*`, `system_settings`). Внешний `LIMIT` добавляется, если его нет.
- **Права — на сервере.** Роль и права берутся из базы при каждом запросе, а не из токена: удалённый или пониженный пользователь теряет доступ сразу. Разделы настроек требуют тех же прав, что и пункты меню.
- **Ключ подписи токенов** — свой на каждой установке (desktop — `secret.key` в каталоге данных, `start.sh`/`start.ps1` генерируют его в `.env`, заглушка из `.env.example` не принимается).
- **Импорт по ссылке** проверяет каждый адрес в цепочке редиректов и не ходит во внутренние сети.
- **Сборка desktop** не содержит базы и `.env` разработчика.

## Решение типичных проблем

### Бэкенд не стартует: `INTERNAL Error: Failure while replaying WAL file`

Повреждение WAL-файла DuckDB. Система автоматически восстанавливается — удаляет повреждённый `.wal` файл и переподключается. Если автоматическое восстановление не сработало:

```bash
rm data/processed/sales.duckdb.wal
./start.sh
```

### WebSocket не подключается при старте

При запуске бэкенд выполняет warmup Ollama (до 15 сек), что может блокировать event loop. WebSocket автоматически переподключается через 3 сек. Если подключение не восстанавливается:

1. Убедитесь что Ollama запущена: `curl http://127.0.0.1:11434/api/tags`
2. Проверьте логи: `cat logs/backend.log | grep "WS:"`
3. Перезапустите: `Ctrl+C` → `./start.sh`

### Ollama warmup failed

Если Ollama не установлена или модель не скачана, бэкенд стартует с предупреждением. Функции ИИ будут недоступны. Решение:

```bash
ollama serve                    # Запуск Ollama
ollama pull qwen2.5:14b         # Скачивание модели
```

### Deprecation warnings при запуске

Предупреждения `regex has been deprecated, please use pattern` — безопасны, не влияют на работу. Устранены в актуальной версии.

### Порт 8000 или 5173 занят

`start.sh` останавливает только прошлый запуск этого же проекта. Если порт занят другим приложением (например, Docker/OrbStack пробрасывает порт контейнера), скрипт его не трогает и запускает сервис на ближайшем свободном порту — итоговые адреса он печатает в конце. Порты можно задать явно:

```bash
BACKEND_PORT=8001 FRONTEND_PORT=5174 ./start.sh
```

Посмотреть, кто занял порт:

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```
