# Sales Analytics — Desktop (Electron)

Desktop-обёртка для Sales Analytics на Electron.

## Быстрый старт (Dev)

```bash
cd desktop
npm install
npm run dev
```

Запустит:
- Frontend dev server (порт 5173)
- Backend FastAPI (порт 8000)
- Electron окно

## Сборка (Production)

```bash
cd desktop
npm run package
```

Собирает:
1. Frontend → `../frontend/dist/`
2. Backend binary → `desktop/build/backend/`
3. Electron app → `desktop/release/`

### Какая модель попадёт в сборку

Перед упаковкой скрипт спрашивает, какую модель встроить в приложение:

- **текущую** — ту, которой сейчас пользуется приложение (выбор в «Настройки → Настройки ассистента», иначе `OLLAMA_MODEL` из `.env`);
- **одну из рекомендуемых** — список общий с приложением (`app/services/model_catalog.py`), для каждой указано, на какой объём памяти она рассчитана;
- **без модели** — установщик получится легче, а подходящую модель пользователь скачает в самом приложении: оно определит конфигурацию компьютера и предложит рекомендуемую.

Без вопросов, например в CI:

```bash
npm run package -- --model current
npm run package -- --model qwen2.5:7b
npm run package -- --model none
BUNDLE_MODEL=qwen2.5:14b npm run package
```

Список моделей: `bash scripts/bundle-model.sh --list`. Если выбранной модели нет локально, скрипт скачает её через `ollama pull`. Файлы модели кладутся в `resources/ollama-models` жёсткими ссылками на `~/.ollama/models`, поэтому место на диске не дублируется. Имя модели записывается в `resources/ollama-models/bundle.json`, и собранное приложение использует её по умолчанию.

Пока запущен сервер приложения, база занята, и скрипт не видит модель, выбранную в интерфейсе, — тогда «текущей» считается модель из `.env`.

### Где собранное приложение хранит данные

База, загрузки и логи — в каталоге данных пользователя (`app.getPath('userData')`: на macOS `~/Library/Application Support/Sales Analytics/`), а не внутри приложения: обновление их не стирает, и установка в каталог только для чтения не мешает запуску. В сборку не попадают `data/` и `.env` разработчика — база создаётся при первом запуске.

Ключ подписи токенов (`secret.key`) генерируется там же при первом запуске — свой у каждой установки. Если задан `SECRET_KEY` в окружении, используется он.

Запускается только один экземпляр приложения: повторный запуск выводит на передний план уже открытое окно.

### Где собранное приложение хранит модели

Ollama в собранном приложении работает с папкой моделей пользователя — `~/.ollama/models` (или `OLLAMA_MODELS`, если задана), той же, что у обычной установки Ollama. Поэтому модели, скачанные в «Настройки ассистента», не пишутся внутрь приложения: туда нельзя писать на Windows (Program Files), а на macOS это ломает подпись.

Встроенная модель при каждом запуске прописывается в эту папку (`main/model-seed.ts`):

- файлы весов — жёсткой ссылкой: мгновенно и без лишнего места; если не выходит (другой диск, macOS запускает приложение из временной копии) — символической ссылкой, а на Windows копией;
- манифест кладётся последним, когда все файлы на месте;
- если у пользователя уже есть рабочая модель с тем же именем, её не трогаем;
- «мёртвые» ссылки после переноса приложения чинятся при следующем запуске.

Так встроенную модель видит и Ollama, установленная отдельно. Если папка пользователя недоступна для записи, приложение запускает Ollama со встроенной папкой, как раньше: встроенная модель работает, но докачать другие не получится.

## Структура

```
desktop/
├── main/              # Electron main process
│   ├── index.ts       # Точка входа
│   ├── preload.ts     # Preload script (contextBridge)
│   ├── backend.ts     # Менеджер backend процесса
│   ├── ollama-manager.ts  # Запуск Ollama
│   ├── model-seed.ts  # Перенос встроенной модели в папку пользователя
│   └── health.ts      # Health check polling
├── scripts/           # Скрипты сборки и запуска
├── resources/         # Иконки приложения
├── package.json       # Зависимости Electron
├── tsconfig.json      # TypeScript конфиг
└── electron-builder.yml  # Конфиг упаковки
```

## Зависимости

- Node.js 18+
- Python 3.10+ (с venv в корне проекта)
- Ollama (опционально, для AI-функций)

## Безопасность

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- Preload script exposes only `electronAPI.platform` and `electronAPI.isDesktop`
